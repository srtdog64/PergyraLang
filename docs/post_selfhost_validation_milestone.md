# Post-Self-Host Validation Milestone

The milestone that answers the one question the architecture work left open: **does
domain-meaning preservation actually pay off in real programs?** AIR/intent/slot/
authority machinery is architecturally sound and minimal (see
`semantics/proofs/IRMinimality.md`), but "is the thing it preserves worth
preserving" is a *product* question that only real use can answer.

This milestone is defined now and **executed after self-hosting completes**
(entry gate below). It is deliberately falsifiable: a negative result is allowed
and informative -- it would mean the meaning-machinery is overhead, not value.

## Entry gate (when this starts)

- Self-host parity green across the tool surface (lexer/parser/semantic/codegen/
  linter, C==LLVM byte-equal) -- already met as of 2026-06-20.
- Capability-5 source-payload retirement closed (BDFL track).
- The *broad* stdlib is written in self-hosted Pergyra during this milestone --
  it is both the usability bulk and the dogfood vehicle. (The *minimal*
  self-host stdlib subset already exists; this is the general-purpose layer.)

## Vehicle

1. The broad **standard library**, written in Pergyra, compiled by the
   self-hosted compiler.
2. The **dungeon-crawler** killer usecase (`project_killer_usecase_dungeon_crawler`)
   -- a domain-rich app where intent/world/zone/role/slot map 1:1 to the game.

These two are the test programs; the criteria below are measured against them.

## Falsifiable criteria (each has a pass/fail, not a vibe)

### V1 -- Differential safety (the core thesis claim)
Freeze a public list of N domain-safety bug classes the thesis claims to catch.
For each: write the bug in the crawler, confirm Pergyra **rejects it at compile
time** (or fail-closes deterministically at runtime where marked), and confirm
a faithful port in a conventional language (TypeScript/C#) **does not**
(compiles, then fails at runtime or silently corrupts).

**The list is FROZEN as of 2026-07-11** (N=10; editing it after the crawler
work starts would invalidate the experiment). `S` = expected static reject,
`R` = expected deterministic runtime fail-close (weaker claim, counted
separately). Each entry names the machinery that must catch it.

| # | Bug class | Claim | Crawler fixture sketch | Machinery |
|---|---|---|---|---|
| 1 | Use-after-release of a resource | S | read player inventory slot after `Release` in a cleanup path | own/ref interproc UAF + slot tag |
| 2 | Release-while-viewed / pin conflict | S | release a pinned map-tile view while a render borrow is live | pin/view frontier checks |
| 3 | Unauthorized action (missing authority) | S | `DealDamage` called from a UI-role context without combat authority | authority/role checks |
| 4 | Undeclared effect propagation | S | helper rolls dice (RANDOM) inside an entry declared pure | effect mask, declared⊇used |
| 5 | Capability escalation | S+R | mod content reads a save file without `file_read` cap | static manifest + runtime cap gate |
| 6 | Cross-world state mutation | S | dungeon world writes town-world merchant stock directly | Channel-only cross-world rule |
| 7 | Evidence-free parallel sharing | S | two arms write one loot counter; arm captures live List | docs/178 boundary rejects |
| 8 | Domain lifecycle violation | S+R | `Drink` on an Empty potion vessel; `Capture` before `Authorize` | lifecycle tracker + state tag |
| 9 | Arithmetic UB (div0 / overflow trap) | R | damage formula divides by zero armor | CheckedArith panic, both backends |
| 10 | Out-of-bounds collection access | R | off-by-one on dungeon grid row | bounds-checked accessors, both backends |

- **PASS**: >= 6 of the 7 S-classes are caught statically by Pergyra and
  missed by the conventional port, AND both R-classes fail closed
  deterministically (same observable on both backends) where the port
  corrupts or continues silently. List and both programs public.
- **FAIL**: most classes are caught by neither, or by both -> the
  domain-meaning layer buys little over a conventional type system.

### V2 -- Evidence as a usable artifact (tests the "AIR product value" risk)
The AIR evidence (authority/effect/intent provenance) must produce a **queryable
audit** of the crawler that answers a concrete operational question -- e.g.
"list every action that can mutate player health and the authority each
requires" -- generated by the compiler, without manual reconstruction.
- **PASS**: the compiler emits the audit and it answers the question correctly
  for the real crawler.
- **FAIL**: you have to grep/reconstruct by hand -> the evidence is decoration,
  not load-bearing, and AIR's cost is not justified by its output.

### V3 -- Legibility (the "more legible than Swift" claim, made measurable)
Pick a set of crawler scenes in Pergyra and a faithful conventional port. Ask
readers unfamiliar with the code: "who acts / what is required / what effects
result?" Measure correct-answer rate, Pergyra vs conventional.
- **PASS**: Pergyra meaningfully higher.
- **FAIL**: no difference -> the domain vocabulary is not actually surfacing
  meaning to readers. (Weakest signal; reported as such.)

### V4 -- Ergonomics convergence (general-app scale)
While writing the stdlib + crawler, keep a **friction log**: every place the
language fights you (missing feature, awkward idiom, workaround).
- **PASS**: friction-per-KLOC declines, and **no new friction *class*** appears
  after the last K modules -- the language stops surprising you.
- **FAIL**: friction stays flat or new classes keep appearing -> the language is
  not converging toward usable; the surface has structural gaps.

### V5 -- It runs (the floor)
The broad stdlib compiles under the self-hosted compiler with C==LLVM parity,
and the crawler is actually playable end to end.
- **PASS**: works.
- **FAIL**: does not -> nothing above is real yet.

## What this does NOT prove

- Not "Pergyra is better than Rust/Swift" universally. It tests whether the
  *specific bet* (domain-meaning preservation) pays off in the *specific target*
  (domain-rich apps). A win here is evidence for the thesis in its home turf, not
  a universal ranking.
- Not performance, not ecosystem, not adoption. Those are separate.

## Why a negative result is still a win

If V1/V2 fail, that is the most valuable possible outcome *before* pouring years
into the meaning-machinery: it would say the cost (dual-backend parity, AIR
evidence, the SoT discipline) is not buying proportional safety/clarity, and the
project should either simplify or re-aim. The milestone is designed to be able to
say "no" -- that is what makes a "yes" mean something.
