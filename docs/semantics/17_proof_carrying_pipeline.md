# 17. Proof-Carrying Compiler Pipeline

Last updated: 2026-06-22

Status: `stage-1-certificate-envelope`

Executable gate: `make proof-carrying-pipeline-test-smoke`.

## Contract

Pergyra's proof-carrying compiler path starts as a proof-carrying IR pipeline,
not as a whole-compiler mechanized proof.

The stable shape is:

```text
source -> AIR/DAG/MIR/ABI facts -> certificate envelope -> verifier -> backend
```

The certificate is a compiler artifact. It is allowed to contain digests,
schema names, required fact names, verifier names, and negative-check policy. It
is not allowed to be a prose-only claim.

## Stage 1: Certificate-Carrying IR

Stage 1 wraps existing owner artifacts into a single envelope:

| Layer | Payload | Required proof-carrying claim | Gate |
| --- | --- | --- | --- |
| AIR | `pgy.air.graph.v1` from `--air-json` | intent/effect/authority/coordination evidence exists, drift count is zero, fallback count is zero for required evidence | `air-json-schema-test-smoke`, `intent-compression-contract-test-smoke` |
| DAG/type | type-resolution metadata and resolver inventory | generic/default/ability decisions are owner facts, not backend rediscovery | `type-resolution-dag-test-smoke`, `type-resolution-resolver-inventory-test-smoke` |
| MIR | `pgy.mir.v1` from `--mir-json` | CFG/source-shape/expression/local facts are present before backend or self-hosted consumption | `cfg-body-dataflow-test-smoke`, `self-host-mir-json-parity-test-smoke` |
| ABI/layout | MIR/runtime ABI facts | slot/pin/layout/niche/ownership shape is fact-owned, not backend-guessed | `abi-ownership-shape-test-smoke`, `raw-escape-contract-test-smoke` |
| Backend | C/LLVM fact-consumption evidence | both backends consume the same owner facts or fail closed | `backend-fail-closed-test-smoke`, `llvm-test-backend-compare` |

The first envelope schema is `pgy.proof-carrying-ir.v1`. It is generated by the
smoke from live AIR and MIR dumps and validates:

- payload schema names;
- SHA-256 digests of the payloads;
- required evidence/fact lists for AIR and MIR;
- zero AIR drift and strict evidence;
- negative rejection when a required certificate fact is removed.

## Stage 2: Mechanized Checker Core

Stage 2 is not "prove the whole compiler". It proves the checker contract:

```text
valid certificate + valid owner payloads => downstream pass may consume facts
missing certificate fact => downstream pass must fail closed
```

Coq belongs here as a model of the checker and refinement boundary. The
implementation still needs live smoke gates that bind the model to current
compiler symbols and JSON fields. A mechanized model without the live checker
does not close the implementation seam.

Stage 2 starts with
[`proofs/ProofCarryingIR.v`](proofs/ProofCarryingIR.v). That model proves the
checker-core rule for the Stage 1 envelope: valid certificates allow downstream
fact consumption, but missing required AIR/MIR facts, a compatibility-success
backend policy, or accepting a deleted required fact forces fail-closed. The
model is bound to the implementation by
`make proof-carrying-adequacy-test-smoke`.

## Backend Rule

Backends may not treat source-level axes as physical runtime artifacts by
default. A `world`, `zone`, `intent`, `role`, `roster`, or `slot` axis is
physical only when a certificate layer carries a fact that requires retention.
Otherwise it must be summarized or erased according to the proof-gated erasure
contract.

## Promotion Rule

A proof-carrying layer becomes beta-stable only when:

- it has a named payload schema;
- it has a named verifier gate;
- the certificate envelope records its digest or explicit manifest-only status;
- at least one negative smoke proves that deleting a required fact fails;
- C and LLVM either consume the certified fact or fail closed.

Until then, it is a certificate envelope layer, not a completed proof-carrying
compiler.
