# Language Keyword Registry

`src/lexer/language_keyword_registry.def` is the semantic source of truth for
Pergyra language-word identity. It is compiler-owned declarative input, not a
C-only table, generated JSON, editor configuration, or documentation mirror.

## Closed inventory

The closed registry contains 145 bytewise-sorted, unique spellings:

- 71 `RESERVED` rows with dedicated native token identities;
- 71 `CONTEXTUAL` rows that remain `TOKEN_IDENTIFIER` at the lexer boundary;
- 3 `SOFT` rows (`current`, `full`, and `none`) used as closed values inside an
  already-selected grammar production.

Every row declares its spelling, lexical class, token/debug identity, broad
parser context mask, language axis, native/self-host support, and tooling
exposure flags. `PGY_KEYWORD_TOKEN_NONE` means that the spelling has no
dedicated lexer token; it must not be promoted to a reserved token merely to
simplify a consumer.

The registry owns whether a spelling is a Pergyra language word. The owning
parser production still decides whether a contextual or soft word is legal at
one exact position. Registry context masks are inventory evidence and a drift
ratchet, not a replacement grammar.

## Derived consumers

- Native lexer lookup and reserved-token debug identity read the registry
  directly.
- The self-host lexer consumes a checked-in Pergyra projection generated by
  `scripts/render_language_keyword_registry.py`; only the 71 reserved rows
  affect lexical classification.
- Native parser selector literals are checked bidirectionally against all 74
  contextual/soft rows. Ordinary identifier data, builtin/type names, effect
  values, and duration suffixes are not language-word rows.
- LSP completion labels are built from `COMPLETION` flags. The closed view has
  27 labels.
- Lowercase language hover content is allowed only for the 25 rows marked
  `HOVER`. The seven PascalCase builtin hover entries remain a separate LSP
  presentation fact and are not language keywords.
- The canonical TextMate view contains the exact 92-row `HIGHLIGHT` projection:
  all 71 reserved rows plus 21 contextual rows. `domain` and `sync` were
  removed because no parser owner accepts them.

The full VS Code grammar remains at
`editor/vscode-pergyra/syntaxes/pergyra.tmLanguage.json`. `editors/vscode` is
the thin LSP client and must not grow a second grammar, `syntaxes` directory,
or `tmLanguage` contribution.

## First falsifiers and ratchets

The first observed defect was `impl/ref/own/type`: the native lexer returned
dedicated tokens, token debug returned `UNKNOWN`, and the self-host lexer copied
that presentation defect as classification. Five more reserved spellings
(`collapse`, `innate`, `local`, `nondeterministic`, and `override`) were absent
from the self-host table. One exhaustive 71-word lexer fixture now prevents
both failures.

The executable gates reject:

- unsorted or duplicate spelling and reserved/contextual/soft collisions;
- invalid class/token combinations or missing reserved debug identity;
- native/self-host reserved-token drift and stale generated projections;
- parser selectors missing from the registry or registry contextual/soft rows
  with no parser selector owner;
- LSP completion, hover, or TextMate words that lack the matching registry
  exposure flag;
- missing highlighted rows, `domain`/`sync` reintroduction, a second TextMate
  grammar, or grammar ownership in the thin VS Code client;
- restoration of a hand-written self-host keyword table or a hardcoded LSP
  completion word array.

Documentation and editor files are projections. If they disagree with the
registry and executable gates, the registry and current parser owners win and
the projections must be regenerated or corrected.
