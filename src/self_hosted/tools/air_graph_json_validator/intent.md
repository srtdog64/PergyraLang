# AIR Graph JSON Validator -- Intent / Contract

**Status:** *rung-2 minimal* (2026-05-27). Reads a stable AIR-graph JSON
dump (`pgy.air.graph.v1`) from a fixture path relative to cwd, validates the
schema field and required top-level keys, extracts summary counts, and emits
the validator schema. No JSON parser; substring-anchored scan only.

## Intent

The AIR graph dump (`pgy --air-json`) is the future-verification surface for
soft self-hosting. Tools downstream from the compiler must trust that the
schema field, summary counts, and required arrays survive every codegen /
runtime change. This tool is the *first* Pergyra-origin gate on that JSON
shape.

## Input Contract

- **fixture_owner**: `src/self_hosted/tools/air_graph_json_validator/fixture/sample.json`
  (text, UTF-8 *without* BOM, single-line `pgy.air.graph.v1` JSON dump).
- The fixture is regenerated by maintainers via
  `pgy --air-json tests/cases/backend_compare/intent_zone_binding/main.pgy`.
  The parity script asserts the live `pgy --air-json` output still byte-matches
  the committed fixture.

The path is fixed relative to repository root; no CLI argument surface yet.

## Output Contract

JSON document on stdout, conforming to schema
`pgy.selfhost.air-graph-validator.v1`:

```json
{
  "schema": "pgy.selfhost.air-graph-validator.v1",
  "ok": true,
  "source": {
    "input_schema": "pgy.air.graph.v1",
    "fixture_owner": "src/self_hosted/tools/air_graph_json_validator/fixture/sample.json"
  },
  "counts": {
    "intents": 1,
    "boundaries": 1,
    "evidence": 12,
    "drifts": 0,
    "missing_keys": 0
  },
  "findings": []
}
```

- `ok = (counts.missing_keys == 0)`.
- `findings[]` carries one entry per problem: `{ "kind": "missing_key" |
  "schema_mismatch" | "input_error", "key": "...", "location": "..." }`.

Exit code: `0` on `ok:true`, `1` on `ok:false`. Missing fixture or
schema-field drift reports findings and exits `1`.

## Oracle

The shell drift detector is `grep -F` against the live AIR JSON for the
required keys plus `grep -oE` for `"id":` occurrences. The Pergyra origin
extracts the summary counts directly from the JSON and the parity script
asserts they match. There is no existing C-side AIR-graph-JSON validator
smoke today, so the Pergyra side is currently the primary implementation and
the shell grep is the auxiliary parity backend.

The parity rung (`src/self_hosted/parity/`) asserts:

- The Pergyra origin exits `0` on the committed fixture.
- Emitted JSON byte-matches `expected/clean.json`.
- Counts match shell ground truth.
- Synthetic missing-key fixture (`summary` key stripped) yields `rc=1` and
  `ok:false`.
- Live `pgy --air-json` re-derived output still matches the committed fixture
  (drift guard).

## Why Now

This is the *third* soft self-host tool. The first two operated on Markdown
inputs; this one operates on stable JSON output of the compiler itself.
It validates that the Pergyra-origin surface
(`ReadFile` + `StringContains` + `StringIndexOf` + `Substring` + `ToInt` +
`StringJoin`) is sufficient to read structured compiler output without a
full JSON parser. If a future tool needs nested array iteration or
`{...}` block walking, that gap surfaces here first.

## Not In Scope

- Full JSON parsing (quoted strings with escapes, nested objects, arrays of
  objects with mixed types).
- Validating *contents* of `intents[]`, `boundaries[]`, `evidence[]` beyond
  count.
- Schema migration (`pgy.air.graph.v2` etc.).
